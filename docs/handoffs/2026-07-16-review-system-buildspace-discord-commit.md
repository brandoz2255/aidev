## What shipped, by area

### 1) Agent review conversation (coder <-> reviewer)
- **`review.py` `run_review_conversation`** — alternating REVIEWER (plain, no-tools critique ending in a structured `VERDICT:` line) and CODER (a bounded `SubAgentRunner` fix-up on the SAME session working tree) loop, up to `HARVIS_REVIEW_MAX_ROUNDS` (default 5). The coder step is never *less* gated than a user turn: same `authorize_action` lane/risk gates, approvals, Phase-3 isolated runner, and the same per-session lock. Its back-and-forth streams through a new **`agent_message`** event under `agent_id=vibecode-review`.
- **`review_status` gate, fail-open** — writes `vibecode_sessions.review_status`: `pending` at start -> `agreed` when no reviewer requests changes -> `needs_human` on round-cap OR **any** internal exception (whole body wrapped so a review crash never wedges the PR gate or the session). No diff -> deterministic approve, no LLM call. Result gates Create-PR; the human override on Create-PR always still works.
- **Custom reviewer roster** — pass `reviewer_ids` and each enabled sub-agent becomes its own reviewer with its **own persona/voice** and a pinned **LOCAL** model (cloud/`anthropic/`/`openai/`/`auto` ids fall back to the shared session model). Agreement requires that **no** reviewer returned `changes`. The reviewer prompt keeps each agent "fully in the voice, persona" of its sub-agent definition — so a user-defined themed reviewer (e.g. the demoed **pirate-voice** reviewer) speaks in-character while the appended VERDICT contract keeps `_parse_verdict` working. Default (no ids) = the single built-in `Reviewer`, **zero behavior change**.
- **New `COMMENT` verdict tier** — a non-blocking observation that neither triggers a coder fix-up nor blocks agreement (prefer it when a reviewer's role is to observe rather than demand fixes). `_parse_verdict` is conservative: anything unparseable counts as `changes`.
- **Thinking-model handling** — `model_router.complete` gains `max_tokens`; `review.py` sizes it per reviewer (8192 for r1/qwq/deepseek/o1/o3/think-matched models, else 4096) so a hidden reasoning pass can't truncate the trailing VERDICT, and `_clean_critique` strips leaked `<think>…</think>`. Each reviewer call is individually try/except'd — one model timing out records a conservative CHANGES_REQUESTED and the loop + other reviewers continue.
- **Thread vs GitHub modes** — `review_github.py` + `mode=="github"` run the same conversation as **labeled comments on a real GitHub DRAFT PR** using the session author's own token: `push_session_branch` (commit + force-push `harvis/vibecode/<id>`, refusing main/master), `open_or_reuse_draft_pr` (reuse existing open PR on 422), `post_comment` (🔎 Reviewer / 🧑‍💻 Coder), `mark_ready` (GraphQL draft->ready flip on approval), persisted to `code_pull_requests`. Setup failures degrade to a thread-only review.

### 2) Build Space v1 + orchestration/exec/jobs/terminal hardening
- **Schema (additive)** — `ORCHESTRATION_SCHEMA_SQL` adds `code_projects` (per-user repo registry: repo_url, default/allowed base branches, branch_prefix), `workspace_pending_approvals`, `code_file_changes`, `code_pull_requests`, plus `vibecode_sessions` columns `project_id, work_branch, head_sha, lifecycle, preflight (JSONB), discord_channel_id, approved_patterns, review_enabled, review_status`. `lifecycle` was added deliberately instead of overloading `status` (that would break `uq_vibecode_active_inplace`). It's an idempotent init string, **not** a versioned migration.
- **Preflight (`preflight.py`)** — persisted pre-run health check (real git repo, origin vs registered repo via `normalize_remote`, base/current branch, HEAD sha, clean tree, structured `blockers[]`); never raises. Wired into `create_vibecode_session`, matched against `code_projects`; blockers 409 for registered/in-place sessions, else lifecycle -> `blocked`/`ready`.
- **Phase 3 isolated runner (SECURITY)** — session `exec`/`run_tests` route through `_exec_isolated` -> `terminal_container.exec_isolated` in a **socket-less sibling container** (cap_drop ALL, no-new-privileges, pids limit, uid 1001, HOME=/tmp, session workspace as the only bind mount, network fail-closed to `none`). Gated by `HARVIS_BUILD_ISOLATED_RUNNER` (default ON, unknown values stay ON, **fail-closed** — never falls back to in-process). Closes the host-RCE hole where AI shell commands previously ran in the docker.sock-mounted backend.
- **Tracked edits + local commits** — `apply_patch` (tracked edit primitive, one `code_file_changes` audit row per edit with before/after blob shas) and `git_commit` (ONE local commit on the work branch, refuses main/master, never pushes). Both classified in `risk.py`, session-only.
- **Durable + session-scoped approvals** — `risk.py` mirrors gated actions into `workspace_pending_approvals` (restart-survivable, `stale:true` flag) and adds approve-for-session (`action_pattern` + `is_session_approved`/`add_session_approval`). `authz.py` checks session approval first and auto-allows a match (source `session_approval`). All DB paths fail-open.
- **Risk-reason plumbing** — `classify_action_risk_with_reason` / `gate_decision_ex` name the exact rule that tripped, ridden on the `approval_request` event so the popup says *why*.
- **Real permission-mode on one-shot REST** — `/api/harvis/exec` + `/jobs` recover the session's ladder rung via `_resolve_permission_mode` (defaults `ask`) and now **403** on any `needs_approval` action instead of the old `permission_mode=None` bypass.
- **Jobs (Phase 5)** — per-job `timeout_secs` (1..86400, clamped to `HARVIS_JOB_MAX_LIFETIME_S`), `POST /jobs/{id}/retry` (re-runs the exact command as a NEW job through a shared `_gate_and_launch`), and durable `log_tail` rebuilt from persisted `terminal_output`.
- **Runner robustness** — `_ws_fingerprint` moved off the event loop (`asyncio.to_thread`), >1MB files fingerprinted by (size,mtime), expanded skip-dirs, `tool` name on `tool_result`. `isolation.collect_changed_files_status` returns M/A/D/R (captures untracked before `git add`) so the diff view can render deletes/new files.
- **workspace_router** — `code_projects` CRUD, `/repo-branches`, dynamic PR base (`_resolve_pr_base`: registry default -> repo's real GitHub default -> main), session lifecycle state machine, read-only browse (`/files`, `/file` with the artifact secret deny-list + realpath containment), agent-review endpoints (`/review`, `/active-review`, Create-PR gate + agreed->stale re-lock on new turns), PR persistence + `/changes` audit, `/workspace-model` + `/active-discord`, and `/vibecode/orchestrate-suggest` (cheap classifier, fails open to suggest=false).

## Known-open items / risks (grounded in the group analyses)
- **Schema is not a versioned migration.** 4 new tables + 9 `vibecode_sessions` columns come from the idempotent init strings in `orchestration/__init__.py` (+ `main.py` for `workspace_jobs.timeout_secs`). Confirm they actually apply on the deploy target before the new endpoints go live — otherwise `workspace_router`/`review.py` 500 on a fresh DB.
- **Live-run freeze never root-caused.** The Open-Run removal + inspector-gated-to-finished-runs is a *mitigation*, not a fix (unpinned CPU peg). Visible UX regression for anyone who relied on opening a live run. Real devtools profiling still owed.
- **`push_session_branch` uses plain `git push -u --force`** (not `--force-with-lease`) and refuses only literal `main`/`master` — any other shared/protected branch name would still be clobbered. Also the token is embedded in the origin URL only for the push and reset right after, but the reset is **not in a `finally`** — an exception between set-url and reset could leave the authed remote URL on disk. Both worth a follow-up.
- **Default-ON surface changes to accept consciously:** `HARVIS_OWUI_EXTERNAL_ENGINES` now defaults `true` (external code engines runnable by default), and `docker-compose.yaml` ships **non-empty default Discord IDs** (channel is effectively "set", approver role empty = anyone in channel), so the `/harvis-code` path may be live against those real IDs unless the deployer overrides them.
- **Compose >= 2.24 required** for the CPU/AMD `devices: !reset []` and the `service_completed_successfully` dep; older compose silently keeps the base nvidia reservation. The owui-builder build fetches pyodide, so `docker compose up --build` needs outbound internet at BUILD time (relevant given the K8s DNS/egress block).
- **Dead/unmounted code introduced or left behind:** `PluginsPanel.svelte` was rewritten 56->644 lines but both its mounts were removed in the same diff (zero references now); `McpShop`/`McpWizard` are orphaned yet got cosmetic blue->gray edits; `AdaptiveSpaceShell` + adaptive surfaces are preserved but unreferenced. `liveCompletionTokens` is now permanently 0 (harmless dead arithmetic). Decide keep-vs-remove.
- **Minor:** verdict-parse regex is copy-pasted verbatim into ThoughtStream + AgentTimeline (extract a shared helper); `list_jobs` computes `log_tail` with an N+1 query per job; `BrowserPanel` iframe uses `allow-scripts allow-same-origin` on an arbitrary user-typed URL (fine as a local preview, noted for security).
- **Needs a live multi-round review to *observe*:** the coder<->reviewer bubbles, the custom-persona (pirate-voice) roster, the COMMENT tier settling agreement, and the GitHub draft-PR mode.
