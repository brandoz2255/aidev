## The bug that would have made this silently wrong (read this)

`moonshot_api.py` lives at the **package root** (`python_back_end/moonshot_api.py`) and was **NOT
bind-mounted** into `harvis-backend` — the backend only mounts `main.py`, `setup_flow.py`, and the
subdirectories (`workspace/`, `owui_compat/`, …). So the container ran the **stale baked-in resolver**:
`get_moonshot_model_id('moonshot/kimi-k3')` returned `kimi-k2.5`, meaning picking K3 would silently
run K2.5.

**Fix:** added the file to the compose backend volumes and recreated — `docker compose up -d backend`
(a mount-add needs a **recreate**, not a `restart`). **Standing gotcha:** any root-level
`python_back_end/*.py` that mounted code imports must itself be explicitly mounted, or live edits never
apply. On a fresh clone / image rebuild this doesn't matter (the Dockerfile COPYs everything) — it's a
live-dev reflection issue only, but it will bite anyone editing root-level modules on this box.
