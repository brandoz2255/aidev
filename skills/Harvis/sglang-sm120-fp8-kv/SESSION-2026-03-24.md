## 🔧 Technical Details

### Architecture

```
┌─────────────────────────────────────────────────────────────┐
│ MHATokenToKVPool (memory_pool.py)                           │
├─────────────────────────────────────────────────────────────┤
│ k_buffer[layer]       [size, heads, dim]  dtype=FP8_E4M3    │
│ v_buffer[layer]       [size, heads, dim]  dtype=FP8_E4M3    │
│ k_scale_buffer[layer] [size, 1]           dtype=FP32        │
│ v_scale_buffer[layer] [size, 1]           dtype=FP32        │
└─────────────────────────────────────────────────────────────┘
                           ↓
           ┌───────────────┴───────────────┐
           ↓                               ↓
┌──────────────────────┐        ┌──────────────────────┐
│ sm120_fp8_kv_cache   │        │ Triton Attention     │
│ (Triton kernels)     │        │ (decode/extend)      │
├──────────────────────┤        ├──────────────────────┤
│ - encode_kernel      │        │ - Reads FP8 buffers  │
│ - decode_kernel      │        │ - Dequantizes on-fly │
│ - per-tensor scale   │        │ - Computes attention │
└──────────────────────┘        └──────────────────────┘
```

### Key Implementation Choices

1. **Per-Token Scale Storage** (not per-layer global)
   - One FP32 scale per token slot
   - Memory overhead: 262K × 4 bytes × 16 layers ≈ 16MB (negligible)
   - Accurate dequantization without recomputation

2. **Triton Over CUDA Kernels**
   - Architecture-agnostic compilation
   - No SM90/SM100 lock-in
   - Compiles to native SM120 instructions at runtime

3. **Scale Buffer Pattern**
   - Follows existing FP4 pattern in `MHATokenToKVPoolFP4`
   - `k_scale_buffer[layer_idx][loc] = scale` stores scale per token location

### Memory Pool Modifications

```python
# In _create_buffers() - allocate FP8 scale buffers
if self.store_dtype == torch.float8_e4m3fn:
    self.k_scale_buffer = [
        torch.zeros((self.size + self.page_size, 1),
                   dtype=torch.float32, device=self.device)
        for _ in range(self.layer_num)
    ]
    # Same for v_scale_buffer

# In set_kv_buffer() - route to FP8 path
if self.store_dtype == torch.float8_e4m3fn:
    self._set_kv_buffer_fp8(layer_id, loc, cache_k, cache_v, ...)
```

## 📝 Session Learnings

### What Went Well (2026-03-24)
- GDN weight loader fix prevents instant EOS with AWQ models
- Triton kernels compile cleanly for SM120
- Scale buffer pattern mirrors existing FP4 implementation
- Docker live mount enables rapid iteration

### What Went Well (2026-03-25)
- ✅ 3B model smoke test passed - FP8 KV working correctly
- ✅ Health check binding fixed with `--host 0.0.0.0`
- ✅ Pre-built image reduces test iteration time

### What Failed (2026-03-25)
- ❌ 27B model fails at default 32K context length
- ❌ Need to start with 8K context and scale up gradually

### Key Insights
1. **FP8 KV is critical for 262K context on single GPU** - 8GB VRAM savings enables batching
2. **Per-token scales are necessary** - Per-layer global scale would lose accuracy on mixed-magnitude KV
3. **Triton is the right tool** - CUTLASS/FlashInfer FP8 kernels are SM90/SM100 only
4. **GDN layers break with quant_config** - Must use `linear_attn_quant_config=None` for AWQ
5. **Start small with 27B** - Begin at 8K context, scale up gradually
6. **REASONING_PARSER=qwen3 required** - Qwen3.5 uses different reasoning format

### Gotchas Avoided
- ✅ Stashed Harvis patches before implementation
- ✅ Started with small model (3B) before 27B
- ✅ Per-token scales (not per-layer global)
- ✅ Triton standalone file (not extending TRTLLM kernel)
- ✅ CUDA 12.9.1 (not jumping to 13.1)

### Gotchas Hit
- ❌ Health check binding - server binds to 127.0.0.1 by default
- ❌ 27B context length - default 32K too high for initial test
- ❌ Missing REASONING_PARSER env var for Qwen3.5
